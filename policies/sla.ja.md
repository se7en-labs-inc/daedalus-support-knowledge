# Daedalusサポートのサービスレベル契約

この文書では、Daedalusのサポートケースにおける初回返信と解決の目標時間を定めます。

## 対象範囲

Daedalusをご利用の方へのサポートは、https://daedalus.support.se7enlabs.com のサポートポータルでのみ提供します。

GitHubのIssueは開発作業のためのものであり、サポート窓口ではありません。

ウォレットの詳細情報、ログ、その他の個人情報をGitHubのIssueに絶対に投稿しないでください。

お問い合わせは英語または日本語で受け付けています。お問い合わせいただいた言語で返信します。

## 優先度

以下の目標時間は、業務時間および営業日を基準に計算します。

| 優先度  | 対象                                                                         | 初回返信      | 解決               |
| ------- | ---------------------------------------------------------------------------- | ------------- | ------------------ |
| P1 緊急 | ブロックチェーン上の資金の安全性に影響する可能性のあるセキュリティ上の脆弱性 | 4業務時間以内 | 1営業日以内        |
| P2 高   | ウォレットの主要機能が利用できない問題、またはその他のセキュリティ上の脆弱性 | 1営業日以内   | 3営業日以内        |
| P3 中   | 回避策が利用可能な機能の低下                                                 | 2営業日以内   | 10営業日以内       |
| P4 低   | 表示上の問題、文書に関する依頼、一般的な質問                                 | 5営業日以内   | 固定の解決目標なし |

### P1 緊急

ブロックチェーン上の資金の安全性に影響する可能性のあるセキュリティ上の脆弱性が報告された場合、そのケースはP1に分類されます。

例：

- ウォレットの所有者以外の人物が、そのウォレットからトランザクションに署名したり送信したりできる可能性のある不具合。
- 復元フレーズ、送金時パスワード、秘密鍵が漏えいする可能性のある不具合。
- インストーラーやリリースファイルが改ざんされたという報告。改ざんされたファイルは、秘密鍵を盗んだり、トランザクションに署名したりするコードを実行する可能性があります。

### P2 高

ウォレットの主要機能が利用できないものの、利用者の資金に危険が及んでいない場合、そのケースはP2に分類されます。ブロックチェーン上の資金の安全性に影響する可能性がないセキュリティ上の脆弱性もP2に分類されます。

Daedalusが起動しない、同期できない、またはウォレットを表示できない場合でも、資金はCardanoブロックチェーン上に保持されています。資金が失われたわけではなく、ウォレットの復元フレーズを使えば、対応する別のウォレットでも復元できます。復元フレーズは、信頼できるウォレットソフトウェアにのみ入力してください。こうしたケースはP2に分類されます。

例：

- アップデート後にDaedalusが起動しない。
- Daedalusがネットワークへの接続を完了できない。
- ステークプールへの委任ができない。
- 秘密鍵、署名処理、トランザクションに影響を及ぼすことのない脆弱性（機密情報ではない情報が表示される不具合など）。

### P3 中

機能が低下していても、利用可能な回避策がある場合、そのケースはP3に分類されます。

例：

- ウォレットの同期が遅いものの、ウォレットは利用できる。
- Daedalusを再起動した場合に限り、ハードウェアウォレットを接続できる。
- トランザクション一覧の読み込みが遅い、または更新するまで古い状態が表示される。

### P4 低

ウォレットの利用に影響しない場合、そのケースはP4に分類されます。

例：

- 表示ラベルや翻訳が間違っている。
- 設定項目の場所について質問がある。
- ヘルプ記事の修正依頼がある。

## 業務時間

業務時間は、米国太平洋時間（America/Los_Angeles）で月曜日から金曜日の09:00～17:00です。太平洋時間には夏時間が適用されます。

米国の連邦祝日は営業日に含みません。祝日が週末に当たる場合は、振替休日の日付を適用します。

1営業日は8業務時間です。

### 日本標準時

日本標準時（JST）は年間を通じてUTC+9であり、夏時間はありません。

| 適用中の太平洋時間 | 太平洋時間のUTCオフセット | JSTでの業務時間 | 日本での曜日   |
| ------------------ | ------------------------- | --------------- | -------------- |
| 太平洋標準時       | UTC-8                     | 02:00～10:00    | 火曜日～土曜日 |
| 太平洋夏時間       | UTC-7                     | 01:00～09:00    | 火曜日～土曜日 |

## 時間の計測開始

ケースの対応時間は、サポートポータルでケースが作成された時点から計測を開始します。

ケースは、次のいずれかの時点で作成されます。利用者がメールアドレスの確認を完了した時点、またはポータルのアシスタントとの会話が担当者に引き継がれた時点です。

## 初回返信

初回返信とは、サポートチームの担当者から最初に送られる返信です。

自動送信メッセージや、ポータルのアシスタントによる返信は含まれません。

初回返信までの時間の計測は、一時停止されません。

## 優先度の設定

サポートチームは、ケースの一次確認時に優先度を設定します。一次確認が行われるまで、すべてのケースの初期優先度はP3 中です。

チームはいつでも優先度を引き上げたり、引き下げたりできます。ケースのページには、現在の優先度とその目標時間が表示されます。

目標時間はケースの作成時点から計算します。

初回返信の目標時間には、初回返信を送信した時点の優先度を適用します。解決の目標時間には、ケースを解決した時点の優先度を適用します。

## 解決

利用者にとって実際に利用可能な対応結果が得られた時点で、ケースは解決とみなされます。該当する結果は次のいずれかです。

- 問題が修正された。
- 回避策または復旧手順の有効性が確認された。
- 質問への回答が得られた。

セキュリティ上の脆弱性の場合、「解決」の意味は異なります。チームは報告内容を検証して深刻度を判定し、報告者と協議して緩和策および情報公開のスケジュールに合意します。その後、修正自体は[セキュリティ情報公開ポリシー](security-disclosure.md)に従って進めます。

## 一時停止

解決までの時間の計測は、次の2つの場合に一時停止します。

- チームが利用者からの返信を待っている場合。
- ケースが開発チームの作業待ちになっている場合。Daedalus自体の修正に加え、cardano-walletなど、Daedalusが依存するコンポーネントの修正待ちも含みます。

ケースのページには、計測が一時停止しているかどうかと、その理由が表示されます。
